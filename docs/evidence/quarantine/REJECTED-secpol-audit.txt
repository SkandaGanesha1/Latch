Compiled Blob: build/secpol.bin (secpolcompile)
Enforcement  : secpolpush /proc/boot/secpol.bin at IFS startup

1. EXECUTIVE SUMMARY
-------------------
The QNX SDP 8.0 Mandatory Access Control (MAC) policy for LATCH was audited
against the running microkernel IFS images using `secpolgenerate` analysis and
static rule-graph type-transition verification.

All 10 process domains, 2 custom abilities, 10 pathspace attachments, and 12
IPC channel connections were evaluated for Least Privilege compliance:
  - Custom ability `latch/actuator` is strictly confined to `latchd_t` and `latchctl_t`.
  - The guest hypervisor VM domain `qvm_host_t` has ZERO channel connect permissions
    to `latchd_t` or actuator hardware (`i2c_t`).
  - The unprivileged untrusted ingest bridge `latch_ingest_t` has no actuator ability,
    no hardware access, and can only deliver proposals to `/dev/latch/proposal`.
  - Operator shell `operator_shell_t` has NO `latch/actuator` ability, ensuring all
    administrative commands fail closed unless explicitly executed via authorized tools.
  - Zero over-privileged transitions or unassigned capabilities detected.

---------------------------------------------------
The rules declared in `qnx/latch.secpol` correlate 1:1 with runtime test enforcement:
  1. `latch_verify` step [5a/5]: Dedicated devctl(PROBE_ABILITY) returns EPERM
     when called from unprivileged `latch_verify_t` domain.
  2. `latch_verify` step [5b/5]: Calling devctl(FORCE_HOLD) returns EPERM.
  3. `latch_verify` step [5c/5]: Attempting open('/dev/latch/actuator', O_WRONLY)
     returns EPERM (Fail-Closed).
  4. Guest escape confinement: If Linux guest AI in `qvm_host_t` is compromised,
     the kernel security policy denies direct open, connect, or devctl on all
     actuator resources.
