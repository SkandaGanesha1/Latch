| **U-1** | `latchctl guest-restart` | The v12 manual test plan lists "Supervisor restart" as `slay latchd` then relaunch per buildfile — an operator procedure, not a command. The v12 upgrade plan calls for an ability-gated `latchctl guest-restart` that kills the guest VM and relaunches it. **Measured on 2026-11-25 on the QEMU AArch64 target:** `slay -9 qvm` from the operator shell **works** (and the ingest sees EOF and releases the proposal writer — the observable handoff), but `on -T qvm_host_t … qvm @qvmconf` is **refused** with `on: Operation not permitted`, because `operator_shell_t` holds no `settypeid` and no `spawn`. | **U-2** | Return-feedback transport (LFBK) on the runtime path | The `latch_feedback_t` codec is built and unit-tested but was **not wired**: the supervisor did not emit it and no host→guest channel carried it.
