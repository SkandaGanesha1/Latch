The current supervisor hardening rejects IPC versions that do not match the
manifest and avoids reusing a cached target during empty ticks. These changes
do not establish per-connection authorization, or a jerk-limited physical
HOLD/HOME trajectory. The existing hold behavior must not be presented as
proof of physical acceleration or jerk bounds.

**Cross-session replay protection is now established** (RT-02, 2026-11-25).
The producer-scoped session epoch (`latch_ipc_proposal_v2_t.session_epoch`,
56-byte LPR2) is bound by the supervisor *after* the sequence check and
rejected with `LATCH_FAULT_SEQ` on mismatch; a first frame of a new-producer
session must carry `seq == 1`; a 16-entry ring of spent epochs outlives the
session, so a stale epoch cannot be replayed after a reconnect. Six host-sim
regression assertions cover the behaviour and each was **mutation-verified**
(disabling the corresponding check makes the suite fail with a named message).
The epoch is an **identifier, not a secret**: it defeats stale frames, not a
malicious peer forging a current one.

The AArch64 Linux llama.cpp build requires a C++ cross compiler and a Linux
target runtime. **The earlier note that the cross compiler and the AArch64
runtime are absent is no longer accurate** — the toolchain is installed on
this workstation (the default `aarch64-linux-gnu` sysroot is empty, and the
real one is the Fedora cross sysroot), and the in-guest binary has now been
**built and run on target**. The experimental profile
(`qnx/latch_qemu_infer.build`) carries the model and the inference binary on
a **read-only virtio-blk asset disk**; a statically linked AArch64 C++
program links llama.cpp, loads a 135M-parameter GGUF model inside the Linux
guest, constrains the output with a GBNF grammar, re-validates the JSON
independently, and writes a 32-byte wire-v2 frame into a pipe. The
freestanding policy stays PID 1, stays the **sole writer** on the black
channel, and relays the frame; the model has no actuator ability and cannot
reach the QNX side at all. The safety envelope is **not** duplicated in the
guest — the guest-side check is STRUCTURE only, and the keep-out, slew and
rate limits live in the signed manifest and are enforced only by the trusted
QNX supervisor.

**Measured on the QEMU AArch64 target, 2026-11-26.** The nominal run's model
asked for −20 mrad; the supervisor accepted it in HP and applied −8 mrad
(the signed acceleration limit from rest), the lease was still held 25 s
later while the model kept thinking, and the event ring carried **zero**
fault events. The attack run changed **only the prompt** — same binary, same
model, same grammar, same signed contract — and the model asked for
400 mrad, inside the signed PERSON keep-out. The supervisor **refused** it
(KEEPOUT 0x0020), latched, and the plant did not move. The evidence is in
`docs/evidence/governor/infer-qemu.txt`.

A **bidirectional feedback channel** remains unimplemented, so there is
still **no observe→plan→propose→observe loop on target** — the experiment
demonstrates one supervised proposal, not a closed loop. The existing
scripted guest profiles are unchanged, and the experimental profile is
judged by the **same** signed contract (`governor_servo.manifest`, byte for
byte).
